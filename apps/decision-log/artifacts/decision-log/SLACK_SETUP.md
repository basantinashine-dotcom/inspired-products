# Slack pilot setup (private Socket Mode)

Decision Log uses Slack Socket Mode. The bot opens an **outbound** connection to Slack; no public webhook URL, incoming HTTP endpoint, or Replit external access token is needed. The Replit Slack user connection is separate from this custom app.

1. Create your own Decision Log app at https://api.slack.com/apps. In **App Manifest**, apply `slack-app-manifest.template.json` to your app. It enables Socket Mode, `/why`, the **Log as decision** message shortcut, the private-channel and `reaction_added` subscriptions, and the **Home** tab with its `app_home_opened` event. Do not create a second app. If adding a new scope, **reinstall to the workspace** to grant it; the Home-tab change itself adds no scope.
2. In **Basic Information → App-Level Tokens**, create an app-level token with the `connections:write` scope. Save it as `SLACK_APP_TOKEN` through Replit Secrets. This is an `xapp-` token, **not** the installed bot's `xoxb-` token. Your `SLACK_BOT_TOKEN` remains required for replying and source links. The old `SLACK_SIGNING_SECRET` is not used in Socket Mode.
3. Publish your Decision Log project as a **private Reserved VM** (always running), with the API Server service included. Do not publish the web frontend as a separate bot or choose Autoscale/Static for the socket consumer. In Replit's environment settings set `SLACK_SOCKET_MODE_ENABLED=false` for **development** and `SLACK_SOCKET_MODE_ENABLED=true` for **production**; do not set it in Shared. The API Server refuses to start a socket outside `NODE_ENV=production` even if the development flag is accidentally switched on. Keep `SLACK_APP_TOKEN` and `SLACK_BOT_TOKEN` in Replit Secrets, and ensure `SLACK_PILOT_TEAM_ID` and `SLACK_PILOT_CHANNELS` are available to production (exactly two channel IDs and names). A development workflow alone stops when the editor closes and cannot host the bot.
4. After publishing, confirm the production server reports **Slack Socket Mode connected for the selected workspace** and both pilot-channel membership checks succeed. Check that the development API server does **not** log a Socket Mode connection. Do not turn on the development socket while the published bot is active. To move the bot back to development, first stop/unpublish the production deployment, then intentionally change the runtime guard and enable the development flag; never run both at once.
5. Once the server reports Socket Mode connected, add the app to **only the two channels in your `SLACK_PILOT_CHANNELS` allowlist** from each channel's **Integrations → Add apps** menu.
6. Add 💡 (`:bulb:`) to a **top-level text message** in either pilot channel to log it as a decision, or use the **Log as decision** message shortcut. In Slack's desktop message menu, hover the **original top-level message in the channel timeline**, click **⋮ → Connect to apps**, then choose **Log as decision** in the **Use a shortcut** dialog (search its name if needed). It may not appear directly in the first ⋮ menu. The bot asks for a reason in the message thread. Reply `reason (shareable): ...` to let `/why` quote the reason, or `reason (reference only): ...` to keep answers source-linked without repeating its text. Both require at least 20 characters. Ask `/why <decision keywords>` in that same channel, or mention the bot with a why question. Reactions to thread replies, bot messages, and other emojis are not logged.
7. To find the short user guide in Slack, open **Decision Log → Home**. The bot publishes the guide when someone opens the Home tab. If your app was already installed, apply the new Home-tab and `app_home_opened` entries to its **live App Manifest** first; editing the local template alone does not update Slack.

The bot enforces the selected workspace and an explicit two-channel allowlist in every handler. `/why` only searches decisions logged in the channel where it is asked; it never shares one private channel's decisions into the other. It never archives whole conversations or processes messages from other channels. Live private-channel records are deliberately excluded from the unauthenticated demo web dashboard. Deleted source messages return a tombstone response.
